# Waterdeep Gallery 本地校对数据库方案

## 当前选择

先采用静态 app 内的浏览器本地存储，而不是马上改成非静态后端。

| 方案 | 是否能上 Vercel | 适用场景 | 取舍 |
|---|---|---|---|
| `localStorage` 本地校对层 | 可以 | 单人校对、临时记录、导出后再纳入项目 | 数据只存在当前浏览器；换设备需导出/导入 JSON。 |
| IndexedDB | 可以 | 字段更多、记录更多、需要更强查询 | 比 `localStorage` 复杂；当前卡牌名校对还没必要。 |
| SQLite + 本地服务 | 不适合作为纯 Vercel 静态部署 | 本机长期编辑、批量管理、复杂检索 | 需要启动服务；应另开目录或分支。 |
| Vercel Postgres/Supabase 等云数据库 | 可以，但不再是纯静态 | 多设备/多人协作 | 需要账号、权限、接口和数据安全设计。 |

## 已实现

`lowd_gallery/index.html` 中加入了本地修改层：

- 使用浏览器 `localStorage` 保存，key 为 `lowd_gallery_local_review_v1`。
- 每张卡可在页面填写 `name`、`possible_lore_text`、`card_text`。
- `building_location` 仍可导入/导出以兼容旧数据和说明书考据，但 gallery 不再展示或编辑“地点”字段。
- 下拉选择“印刷版”时，编辑器保存的是 `zh_printed` 的本地覆盖，而不是另存为“本地校对”。
- 下拉选择“中文校译”时，编辑器保存的是 `zh_codex` 的本地覆盖。
- 下拉选择“英文原文”或“版本对照”时，编辑器仍保存到独立的“本地校对”层。
- “版本对照”会同时显示英文原文、固定翻译版本和本地校对版本；被本地覆盖的固定翻译版本会标记为“本地修改”。
- 可导出 `waterdeep_local_review_YYYYMMDD.json`，其中包含每个被修改版本的目标版本 ID。
- 可导入同结构 JSON。

导出的 JSON 结构：

```json
{
  "schema_version": 2,
  "label": "本地修改",
  "source": "Browser localStorage export from lowd_gallery",
  "exported_at": "2026-06-02T00:00:00.000Z",
  "cards": {
    "LW_Buildings_01": {
      "name": "本地校对层名称"
    }
  },
  "versions": {
    "zh_printed": {
      "version_id": "zh_printed",
      "label": "印刷版",
      "source": "Browser localStorage export from lowd_gallery",
      "cards": {
        "LW_Buildings_01": {
          "name": "商队广场"
        }
      }
    }
  }
}
```

旧版只含 `version_id: "zh_local_review"` 和顶层 `cards` 的导出仍可导入；新版会把这类数据导入到独立“本地校对”层。

## 何时升级

如果只是你自己校对译名，继续用静态 app + 本地导出即可。

如果要多人同时改、需要登录、需要跨设备自动同步，建议新建分支或新目录做 `SQLite/API` 或云数据库版本，不要和当前纯静态 Vercel 版本混在一起。
